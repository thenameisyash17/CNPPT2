01 · THE TRANSPORT LAYER

The transport layer connects applications

IP moves packets between hosts; the transport layer moves data between applications on those hosts. Port numbers identify the sending and receiving applications. TCP and UDP sit above IP and below application protocols.

Application

Web, video, games, DNS

Transport

TCP or UDP
Ports and delivery behavior

Network

IP addresses and routing

Application data becomes transport segments or datagrams, then IP packets.

TCP starts with a three-way handshake

Before data transfer, both endpoints agree to begin a connection and synchronize sequence numbers.

CLIENT (Host A)
SYN →
SERVER (Host B)
01

CLIENT → SERVER

SYN

Client requests a connection and synchronizes initial sequence number.

02

SERVER → CLIENT

SYN + ACK

Server accepts request, acknowledges client sequence, and sends its own sequence number.

03

CLIENT → SERVER

ACK

Client confirms acknowledgment. Three-way handshake complete: Connection Established.

03 · TCP SEGMENT FORMAT

TCP headers carry delivery control

32-BIT ROW FIELD BITS
1 Source Port · Destination Port 16 + 16
2 Sequence Number 32
3 Acknowledgment Number 32
4 Data Offset · Reserved · Control Flags · Window Size 4 + 6 + 6 + 16
5 Checksum · Urgent Pointer 16 + 16
— Options and Padding, if present Variable
FIELD PURPOSE
  • Sending application · Receiving application
  • Order and loss detection (Sequence tracking)
  • Next byte expected from peer (ACK number)
  • Header size, session state & flow control (Window)
  • Integrity validation (Checksum) & urgent data
  • Extends and aligns header on 32-bit boundary

05 · UDP · USER DATAGRAM PROTOCOL

UDP keeps communication lightweight

UDP is connectionless: independent datagrams need no session.

Low overhead

Small headers and no handshake mean fast setup and instant transmission.

Few built-in guarantees

UDP does not promise delivery, ordering, or retransmission.

Online gaming

Online gaming favors fresh player positions over recovered old updates.

Real-Time Latency Priority Fresh state > Retransmitted stale frames
< 15ms ping

The trade-off: less waiting and less overhead, with less delivery control.

08 · SIDE-BY-SIDE

TCP and UDP make different trade-offs

CHARACTERISTIC TCP UDP
Connection type Connection-oriented (Handshake required) Connectionless (Immediate dispatch)
Reliability and ordering Built in (Guaranteed in-order delivery) Not guaranteed (Best effort)
Acknowledgements Yes (ACK for received segments) No built-in ACK
Retransmission Yes (Automatic on lost/damaged packets) No built-in retransmission
Minimum header 20 bytes 8 bytes
Overhead Higher (Header fields & connection state) Lower (Minimal processing overhead)
Common applications Web (HTTP/S), file transfer (FTP), email (SMTP) Gaming, live media streaming, DNS, DHCP, VoIP

TOPIC · CONNECTION ORIENTATION
"Why is TCP called Connection-Oriented while UDP is Connectionless?"

TCP: Connection-Oriented

3-WAY HANDSHAKE
  • Handshake Setup: Negotiates sequence numbers (SYN → SYN-ACK → ACK) before sending data.
  • Stateful Session: Both endpoints track active state until connection is closed with FIN.

UDP: Connectionless

FIRE & FORGET
  • Zero Setup: Packets dispatch immediately with no prior handshake or session setup.
  • Stateless: Kernel maintains no connection tables; each datagram travels independently.

TOPIC · PROTOCOL HEADER OVERHEAD
"Why is TCP's minimum header 20 bytes while UDP is only 8 bytes?"

TCP: 20 Bytes Minimum

CONTROL-RICH
  • Control Fields: Needs Sequence No., ACK No., Window Size, and 6 control flags.
  • Reliability Cost: Header overhead is required for in-order delivery and error recovery.

UDP: 8 Bytes Fixed

LEAN & FAST
  • 4 Fields Only: Source Port, Destination Port, Length, and Checksum (2 bytes each).
  • 60% Less Overhead: Strips away sequencing and flow control for minimal packet size.

TOPIC · LATENCY & REAL-TIME AUDIO
"Why do real-time VoIP audio calls and Discord voice prefer UDP over TCP?"

Strict Latency Limit (<150ms)

REAL-TIME
  • Human Interactivity: Two-way spoken audio conversation degrades noticeably if delay exceeds 150ms.
  • No Freezing: TCP retransmissions halt audio playback and cause intolerable call stutter.

Freshness Beats Recovery

TOLERATES LOSS
  • Late Audio is Junk: An audio packet arriving 300ms late is discarded by the speaker codec anyway.
  • Glitch > Delay: Dropping a tiny millisecond sample is imperceptible compared to conversation lag.

TOPIC · PACKET LOSS HANDLING
"What happens when a packet is dropped in TCP versus UDP?"

TCP: Auto Retransmission

RELIABLE RECOVERY
  • Loss Detection: Detects missing ACK via timer expiration (RTO) or 3 Duplicate ACKs.
  • Resend & Throttle: Automatically resends lost segment and lowers send rate to relieve congestion.

UDP: Silent Loss

BEST EFFORT
  • Silent Drop: No ACK mechanism exists; sender is completely unaware of the dropped packet.
  • Zero Kernel Recovery: Lost packet is gone forever unless application code implements retries.

TOPIC · PROTOCOL APPLICATION MAPPING
"Name 2 common protocols that use TCP and 2 that use UDP, with brief technical reasons."

TCP: HTTP/S & SSH

ACCURACY CRITICAL
  • HTTP / HTTPS: Web pages and REST APIs cannot tolerate corrupted characters or lost bytes.
  • SSH / FTP: Remote shells and file transfers require 100% exact bit-for-bit delivery.

UDP: DNS & DHCP

SPEED CRITICAL
  • DNS: Fast 1-packet lookup; connection handshake would double domain resolution time.
  • DHCP: Broadcasts IP settings to devices before any TCP connection can be established.
